# שלב ה' — ממשק משתמש גרפי (GUI)
## מערכת לניהול מעבדה רפואית (Medical Laboratory Management System)

ברוכים הבאים לממשק המשתמש הגרפי של מערכת המעבדה הרפואית. ממשק זה נבנה בשפת **Python** תוך שימוש בספריית **CustomTkinter** ומאפשר לנהל את בסיס הנתונים PostgreSQL בצורה ידידותית, מודרנית וויזואלית, כולל תמיכה מלאה באינטגרציות ובכלים שנבנו בשלב ד' (פרוצדורות, פונקציות וטריגרים).

---

## 🛠️ טכנולוגיות וכלים
- **שפת פיתוח:** Python 3.x
- **ספריית ממשק משתמש:** CustomTkinter (חלונות מודרניים, כפתורים מעוצבים, מראה ייחודי ותמיכה מלאה במצב כהה/בהיר)
- **חיבור לבסיס הנתונים:** Psycopg2-binary (לניהול חיבורים וביצוע שאילתות ישירות מול PostgreSQL)
- **ניהול הגדרות:** Python-dotenv (לטעינה מאובטחת של פרטי החיבור מקובץ סודי)
- **ניהול תהליכים (בסיס נתונים):** Docker & Docker Compose להרצת PostgreSQL ו-pgAdmin מקומית

---

## 🚀 הוראות כניסה והפעלה של המערכת

### דרישות קדם (Prerequisites)
1. ודאו שמותקן אצלכם במחשב **Python 3.10** ומעלה.
2. ודאו שבסיס הנתונים PostgreSQL (בתוך קונטיינר Docker או שירות מקומי) פועל ומכיל את טבלאות המעבדה.
   * אם אתם משתמשים ב-Docker Compose של הפרויקט, הפעילו את בסיס הנתונים דרך המסוף:
     ```bash
     docker compose up -d db
     ```

### שלבי התקנה והרצה
1. פתחו את מסוף הפקודות (Terminal / PowerShell) ונווטו לתיקייה זו:
   ```bash
   cd "DBProject_5786_3680_0282/שלב ה"
   ```
2. צרו סביבה וירטואלית חדשה כדי לשמור על סדר בהתקנות:
   ```bash
   python -m venv .venv
   ```
3. הפעילו את הסביבה הווירטואלית:
   * **בחלונות (Windows PowerShell):**
     ```powershell
     .venv\Scripts\Activate.ps1
     ```
   * **בחלונות (Cmd):**
     ```cmd
     .venv\Scripts\activate.bat
     ```
   * **בלינוקס / מק (Linux / macOS):**
     ```bash
     source .venv/bin/activate
     ```
4. התקינו את הספריות הנדרשות מתוך קובץ הדרישות:
   ```bash
   pip install -r requirements.txt
   ```
5. הגדירו את קובץ הגדרות החיבור (`.env`):
   * העתיקו את הקובץ הדוגמה שקיבלתם:
     ```bash
     copy .env.example .env
     ```
   * פתחו את קובץ `.env` החדש שנוצר ועדכנו את פרטי הגישה של בסיס הנתונים שלכם (כתובת השרת `DB_HOST` כשרצים מקומית צריכה להיות `localhost`, שם המשתמש והסיסמה).
6. הריצו את הממשק הגרפי:
   ```bash
   python main.py
   ```

## 🖥️ תיאור מסכי המערכת ותפקודיהם

המערכת מחולקת למספר חלקים מרכזיים הנגישים מתוך תפריט הצד (Sidebar):

### 1. לוח בקרה (Dashboard)
המסך הראשי של המערכת המציג את סטטוס החיבור לבסיס הנתונים (גרסת PostgreSQL הפעילה), מספק קישורים מהירים למודולים השונים ומאפשר החלפת ערכת נושא (Toggle Theme) בין **מצב כהה (Dark Mode)** ל**מצב בהיר (Light Mode)**.

### 2. ניהול נתונים (CRUD)
מסך גנרי חכם המאפשר ניהול של כל 6 הטבלאות במערכת:
* **טבלאות נתמכות:** הזמנות מעבדה (`LAB_ORDER`), בדיקות מעבדה (`LAB_TEST`), תוצאות בדיקה (`LAB_RESULT`), טכנאי מעבדה (`LAB_TECHNICIAN`), ציוד דיאגנוסטי (`DIAGNOSTIC_EQUIPMENT`), ובדיקות בתוך הזמנה (`LAB_ORDER_TEST`).
* **חיפוש ושליפה (Read):** הזנת מפתח ראשי ולחיצה על "Load" טוענת את הנתונים ישירות לטפסים. טבלת תצוגה מציגה את כל הרשומות הקיימות.
* **עדכון ויצירה (Create / Update):** כפתור "Save" מזהה אוטומטית אם מדובר ברשומה חדשה (ביצוע Insert) או קיימת (ביצוע Update) ושומר אותה בבסיס הנתונים.
* **מחיקה (Delete):** כפתור מחיקה להסרת רשומות מבסיס הנתונים עם שגיאות ידידותיות במקרה של אילוצי מפתח זר.
* **נוחות משתמש:** שדות המפתח הזר מציגים רשימת בחירה (Dropdown) עם תיאורים ברורים של הרשומות (לדוגמה: שמות הטכנאים במקום מספרי מזהה בלבד).

### 3. דוחות ושאילתות אנליטיות (Analytics)
הרצה של שאילתות מורכבות משלב ב' ושלב ד':
* **שאילתות מורכבות:** הפעלת דוחות כמו ניתוח הבדיקות הפופולריות ביותר, מעקב אחר הזמנות דחופות וציוד הדורש טיפול.
* **פרוצדורות מבוזרות (Stage 4):**
  * כפתור לחישוב וסנכרון סך מחירי ההזמנות (`pr_update_all_order_prices`).
  * כפתור לקידום והענקת בונוסים לטכנאים מצטיינים (`pr_promote_technicians`) עם אפשרות להגדרת מינימום בדיקות וכמות נקודות בונוס.
  * המערכת מציגה את יומן הפעילות (Notice Logs) שנשלח מהשרת ישירות בתוך תיבת דו-שיח ייעודית.
* **פונקציות ואינטגרציות (Stage 4 & Stage 3):**
  * הפעלת הפונקציה `fn_get_doctor_workload` המקבלת מזהה רופא ומחזירה סמן (Cursor) של עומס עבודתו. המערכת מאפשרת לבחור את הרופא מתוך רשימת בחירה הנטענת ישירות ממערכת ה-Staff החיצונית ששולבה בשלב ג' (`staff_remote`).

### 4. טיפול בשגיאות ואכיפת אילוצים (Database Constraints & Triggers)
במידה ומנסים לבצע פעולה הנוגדת את חוקי העסק המוגדרים בבסיס הנתונים (כמו הוספת בדיקה להזמנה שכבר הושלמה אשר נחסמת על ידי הטריגר `trg_status_protection`), המערכת מזהה את השגיאה מהשרת ומציגה הודעת אזהרה מותאמת אישית וידידותית למשתמש במקום לקרוס.
